### 二、 最重要的 5 項問題（按優先順序與執行指導）

#### 1. 結算反饋字串拼接邏輯錯誤，導致老闆台詞與玩家實際作答矛盾
* **涉及 ID**：`result-high-score-proposal-b`、`result-high-score-proposal-c`、`result-low-score-proposal-a`
* **問題說明**：在 `result-high-score-proposal-b` 與 `c` 中，玩家第一輪已完全答對4項痛點（c01, c02, c03, c18），老闆開場卻機械式吐出「你有抓到一項我們剛才談到的新客困擾」，直接否定玩家表現；在 `result-low-score-proposal-a` 中，玩家痛點全錯卻選了A，老闆一邊盛讚A方案踏實，一邊斥責不要腦補未到場原因，前後自相矛盾、情緒分裂。
* **改寫指導**：結算引擎需區分「全對」、「部分對」與「全錯」的條件判斷分支，不得共用「你有抓到一項」的死板預設字串；老闆反饋應先對第四輪主方案表態，再以「但在前面的顧客痛點上…」進行轉折，避免多個獨立評語硬湊成一塊。

#### 2. 教學解析外洩系統提示詞（Prompt Leak）
* **涉及 ID**：`ideas-c11`（explanation）、`ideas-c15`（explanation）
* **問題說明**：題解文字出現「示範不允許模型判斷個人安全或健康問題…」、「示範只把匿名問題分類…」。這是開發規格書或Prompt規則外洩，完全破壞遊戲世界觀與教學沉浸感。
* **改寫指導**：全面刪除「示範」、「模型」字眼，回歸行銷企劃角度。改寫為：「AI草擬的問答無法代替專業教練評估學員的身體狀況與訓練安全…」及「AI整理的問題分類只能當作參考草稿，不能直接推論為全體顧客的偏好…」。

#### 3. 「防禦性免責句」機械式反覆出現，削弱經營者現場感
* **涉及 ID**：`persona-q4`、`persona-q7`、`persona-q8`
* **問題說明**：為了落實「未經確認的事不能亂補」，老闆在多個回答中幾乎使用完全相同的句型結尾：「那天沒聊到／等下次有機會碰面再問問」。這種重複呈現出強烈的AI防禦提示詞痕跡，缺乏真人交談的情境流動。
* **改寫指導**：保留「事實未確認」的原則，但應以真實經營者的現場反應來包裝。例如被問到接待偏好時，老闆可以說：「那天他話不多、眼神一直在看門口課表，我也拿不準他是想自己看還是要人帶，現場櫃檯正忙，我就沒硬拉著他推銷。」透過情境動作交代「為何沒問」，而不是每次都宣告「我沒聊到」。

#### 4. 老闆對白滲入不符角色的企管與軟體術語
* **涉及 ID**：`needs-q1`、`blueprint-q3`、`ideas-intro-6`、`resultSamples`（多處 bossComment）
* **問題說明**：林老闆是大學旁小型健身房老闆，尖峰只有一名櫃檯。但他卻說出「理順」（大陸用語/公文詞）、「後台立刻更新頁面並通知前線」（大型企業或SaaS軟體用語）、「綜合衡量」（企管顧問腔），甚至在結算時說「把現有人手跟事實依據核對清楚」（教科書詞彙）。
* **改寫指導**：
  * 「我想把這些基本資訊理順」→ 改為「我想把這些基本資訊整理清楚／弄順一點」。
  * 「後台立刻更新頁面並通知前線」→ 改為「我們後台改一下網頁，趕快跟當班同事講一聲」。
  * 「事實依據」→ 改為「客人到底怎麼說、我們現場到底做不做得到」。

#### 5. 專家講評（expertComment）高度模板化，缺乏動態診斷價值
* **涉及 ID**：`result-mixed`、`result-poor`、`result-low-score-proposal-a` 等
* **問題說明**：專家評語首段在多份樣本中皆原封不動複製貼上「提案若能嚴格劃分『已確認事實』、『合理假設』與『待補問資訊』…」，如同罐頭訊息。在低分樣品中，專家沒有指出玩家為何在明明選對A方案的情況下依然整體失敗，教學指導流於形式。
* **改寫指導**：精簡通用開場白，直接針對玩家本局最大的「斷裂點」開刀。例如當玩家選A但痛點全錯時，專家應點出：「你雖然挑中了可行性最高的一頁介紹頁，但在前端把『客人不來』全怪罪給『價格太貴』，這會導致介紹頁文案抓錯重點。」

### 三、 具體修改範例（列 ID 與修改理由）

1. **`blueprint-q3`（林老闆回覆）**
   * **原文**：「…要是時段或人手有臨時異動，後台立刻更新頁面並通知前線，避免客人到了現場才發現對不上。」
   * **問題**：「通知前線」是大型連鎖或軍事/IT用語，違背單店小型健身房人設。
   * **建議改寫**：「…要是時段或人手臨時有變動，後台網頁趕快改一下，也立刻跟櫃檯同事交代一聲，免得客人人都到了才發現撲空。」

2. **`ideas-c11`（題解說明）**
   * **原文**：「示範不允許模型判斷個人安全或健康問題，且 C 明確要求避免不必要健康資訊。」
   * **問題**：系統提示詞直接洩漏給玩家，毫無教學包裝。
   * **建議改寫**：「個人的身體狀況與動作訓練涉及安全問題，必須由現場合格教練當面評估，絕對不能交給AI或未經核對的文字做承諾。」

3. **`result-high-score-proposal-b`（林老闆結算評語）**
   * **原文**：「你有抓到一項我們剛才談到的新客困擾，這部分值得先處理。固定帶看能讓新朋友親眼看到場地…我們一定要先把現有人手跟事實依據核對清楚。」
   * **問題**：玩家痛點選對4項卻被說成「抓到一項」；且「事實依據」語帶官腔。
   * **建議改寫**：「你把剛才談到的新客困擾都抓得很準，這幾點確實該先解決。固定帶看能讓新朋友親眼看到場地，出發點很好；但我這週根本還沒排定帶看的人員跟空檔…我們一定要先看店裡現場到底接不接得住，不能光憑想像先對客人承諾。」

4. **`persona-q4`（林老闆回覆）**
   * **原文**：「那天主要在問時間和報到方式，沒有聊到比較喜歡自己看說明，還是希望有人帶著了解。這部分我得找機會再問問本人，才知道哪種安排用起來比較方便。」
   * **問題**：公式化宣告「沒聊到／再問問」，缺乏情境。
   * **建議改寫**：「那天他主要是急著對課表跟打工時間，問完報到就差不多了。我看他好像趕時間，就沒多問他到底習慣自己看介紹、還是想找人帶看。這點之後碰面我再順口問問他。」

5. **`needs-q1`（林老闆回覆）**
   * **原文**：「最棘手的就是大家想來體驗，卻在門口或電話裡卡住…我想把這些基本資訊理順，讓客人出門前心裡有數…」
   * **問題**：「理順」非台灣道地口語。
   * **建議改寫**：「最棘手的就是大家想來體驗，卻在門口或電話裡卡住…我想把這些基本資訊整理清楚，讓客人出門前心裡有數…」
